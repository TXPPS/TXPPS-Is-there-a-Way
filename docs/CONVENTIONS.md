# Conventions

## Files and naming

| Thing | Convention | Example |
|---|---|---|
| Scripts, scenes, resources | `snake_case` | `virtual_stick.gd`, `graybox_room.tscn` |
| Classes (`class_name`) | `PascalCase`, matching the filename | `VirtualStick` |
| Nodes in a scene | `PascalCase`, named for their role not their type | `BulkheadLamp`, not `OmniLight3D2` |
| Constants | `SCREAMING_SNAKE` | `STAMP_PATH` |
| Private members | leading underscore | `_look_target`, `_apply_look()` |
| Booleans | read as an assertion | `invert_y`, `shadow_enabled` |
| Directories | one concern each | `src/input/`, not `src/misc/` |

Scenes live next to the script that drives them. A folder with one `.tscn`, its
`.gd`, and its `*_tuning.tres` is the unit of work.

## GDScript

- **Type everything.** `var speed: float = 0.0`, `func f(x: int) -> void:`.
  `project.godot` turns on `untyped_declaration`, `unsafe_property_access` and
  `unsafe_method_access` warnings; keep the log clean.
- **Small, single-purpose functions.** If `_physics_process` does three things,
  it calls three functions named after them.
- **No file over ~300 lines.** Past that, the file is doing two jobs.
- **No magic numbers.** Anything a designer might want to change is an `@export`
  on a tuning `Resource`. Anything else gets a `const` with a name.
- **Shallow nesting.** Prefer an early `return` over an `else`.
- **Composition over inheritance.** A node gains behaviour by having a child or
  a resource, not by subclassing three levels deep.
- **`assert()` your wiring.** `assert(tuning != null, "...")` in `_ready()` turns
  a forgotten inspector slot into a message instead of a null crash ten frames later.

## Signals vs. direct reads

- **Signal** when something *happened*: a drag delta arrived, a valve reached its
  stop, the entity noticed you. Past tense, named for the event: `looked`,
  `door_sealed`.
- **Direct read** when something *is*: the stick's current deflection, the fear
  scalar. Reading a value that is meaningful every frame is not polling.
- Never poll for a change you could have been told about.
- Connect signals in the composition root (`src/main.gd`) or in the owning
  scene's `_ready()`. Not from a grandchild reaching up the tree with `get_parent()`.

## Comments

Comment the *why*, never the *what*. `walk_speed = 1.95` does not need
"the walk speed"; it needs "an auditor with a clipboard walks; he does not jog."

Use `##` doc comments on `class_name` classes and on exported properties — they
show up in the inspector, which is where the tuning actually happens.

## Assets

Every asset is generated by a committed script under `tools/gen/`, and the
generated output is committed alongside it. CI regenerates and fails if the
result differs, which keeps "regenerable" true rather than aspirational.

No third-party asset packs, no royalty-free libraries, no AI-generated textures.

## Resources vs. project settings

- `project.godot` holds engine and platform configuration: renderer, display,
  physics tick, input map, layer names. Nothing about feel.
- `*_tuning.tres` holds feel. If a designer would want to change it, it goes here.

## Changes and risk

Before a refactor that touches more than one system, **name the regression risk
first**, in the commit message or in `PROGRESS.md`. When debugging, rank likely
root causes by probability, apply the smallest safe fix, and confirm it. No
speculative rewrites.

## Commits

Present tense, scoped, and about the change rather than the file:
`fence tools/ from the resource scanner so node_modules stays out of the pack`.
