# Architecture

## Constraints that shape everything

The target is one device: an iPhone 16 Pro Max running Safari, in landscape,
possibly in Low Power Mode, loading over LTE. That produces four hard rules
that every design decision below answers to:

1. **Compatibility renderer only** (WebGL2). No SDFGI, SSAO, SSIL, SSR, or
   volumetric fog — they do not exist in this backend. Verify a technique works
   under Compatibility before building on it.
2. **Single-threaded web export.** No `SharedArrayBuffer`, therefore no COOP/COEP
   headers, therefore the game can be served from any static host.
   `tools/ci/postprocess_web.py` fails the build if this ever regresses.
3. **Text-only project formats.** `.tscn`, `.tres`, `.gd`. No `.scn`/`.res`, no
   Git LFS. The project must be openable and hand-editable in the desktop editor
   years from now.
4. **Budgets are enforced, not aspirational.** See `BUDGETS.md`;
   `tools/ci/check_budgets.py` fails the build on a breach.

`tools/.gdignore` matters: without it, Godot imports `tools/web/node_modules`
into the game data pack. It did, once. The `.pck` went from 74 KB to 25 MB.

```
│   ├── LookPad (Node)               drag-to-look, when that style is selected

│   └── HudRects (Node)              the reserved rect registry
└── PauseMenu (CanvasLayer)          src/ui/pause_menu.tscn, process_mode ALWAYS
```

The build stamp is **not** in this tree. It lives in the HTML shell, where it is
still readable when the engine has failed to boot — which is exactly when you
most want to know which build you are looking at. The pause menu shows the same
string at its foot and copies through the same shell function, so a report is
identical wherever it was tapped.

**No autoloads.** Global state is a decision, not a convenience. `Settings` is a
node in the composition root and is handed to whoever needs it by `src/main.gd`.

`src/core/` still holds P1 scaffolding that is written but **not yet wired**:
`game_state.gd` (the FREE/FOCUSED/MENU/CINEMATIC/DISABLED machine),
`surface_type.gd` and `src/world/surface_tag.gd` (the footstep-audio hook P3
needs). They cost nothing at runtime and are listed here so nobody goes looking
for the systems they imply.

## Touch ownership

Every screen touch the HUD cares about goes through **one** `TouchRouter`, under
two rules:

1. A touch is claimed by whichever registered region it *begins* in, and the
   claim holds until the touch is released — even if the thumb drags far outside
   that region. Nothing else may act on a claimed touch.
2. Movement is derived here, from that touch's own previous position, keyed by
   touch index. `InputEventScreenDrag.relative` is **never** read.

Rule 2 is not fastidiousness. Godot 4.6's web display server keys its
previous-position table by the touch's slot in the DOM event's `changedTouches`
list rather than by the touch identifier it stamps on the event
(`platform/web/display_server_web.cpp`, `Point2 &prev = ds->touches[i];`). With
two thumbs down, the right thumb's `relative` is measured from wherever the
*left* thumb last was — hundreds of pixels, every move event. That was the
camera spinning on device. Deriving the delta from `position`, per index, is
immune to it, and `tests/case_input.gd` lies in the `relative` field on purpose
to prove nothing downstream reads it.

Two more guards ride along, cheap and unconditional: the first move of any claim
reports zero travel (whatever the platform thought the previous position was, we
did not measure it), and every delta is clamped to `max_touch_delta`, so a
cancelled-and-re-issued touch is a small error rather than a spin.

Registration order is priority: pause button, then the sticks, then — under the
drag look style only — a region covering everything else.

## Reserved HUD rects

`HudRects` is the registry of screen area the controls own. A reserved rect is a
promise: a thumb resting there is already doing something, so

- nothing else may be **drawn** there — prompts, subtitles, toasts, banners;
- nothing in the world may be **targeted** through it (`blocks_point()`).

Providers are `Callable`s returning a `Rect2` in viewport units, called on every
query, so a rect that moves with the safe area or a settings change is current
without anyone re-registering.

| Call | Use |
|---|---|
| `reserve(id, provider)` | claim area; registering the same id twice replaces it |
| `release(id)` | give it back (the look stick does this under drag look) |
| `rects()` | every live rect, `id -> Rect2` |
| `is_clear(area)` / `conflicts(area)` | may I draw here, and if not, what is in the way |
| `blocks_point(point)` | is this screen point under a control |
| `require_clear(who, area)` | assert it, and report an overlap as a runtime error |
| `describe()` | flattened for the debug overlay and the browser suite |

**Every future HUD element registers against it.** An element that owns space
calls `reserve`; an element that merely wants space calls `require_clear` when it
is placed and when the layout changes. On the phone a violation surfaces as an
error toast; in CI it fails `tests/case_layout.gd`, which asserts that no two
reserved rects overlap and that everything drawn is inside the safe area.

The claim region and the reserved rect are deliberately the same thing, and both
are larger than the ring you can see: a stick you have to hit dead centre is a
stick you look down at. What has to clear the notch and the home indicator is
what is *drawn*, which is why the two are asserted separately.

Action buttons (interact, flashlight, crouch) are already reserved, three slots
on an arc swung around the look stick, before any of them exist — so nothing
else settles into the space they will need.

## Settings

One `SettingsSpec` resource is the whole menu and the whole preference set.
Adding a preference is a row in `assets/settings/settings_spec.tres` plus one
`match` arm wherever it applies; there is no screen to edit, so there is no way
to ship a setting that saves but is never shown, or is shown but never saved.

Every value is a float — a toggle is 0 or 1, a choice is an index — which makes
serialisation, clamping, migration and the widget code one path instead of four.

Writes persist immediately through `src/core/storage.gd` (IndexedDB with a
synchronous localStorage mirror on the web; one JSON file under `user://` off
it). There is no Apply button and no save-on-exit, because a phone does not
reliably get an exit. Every change also emits `changed`, and `src/main.gd` fans
that out to the player, the HUD and the mixer, each of which takes the keys it
owns and ignores the rest. Nothing here needs a restart.

## Data flow

Input is pushed, not pulled from across the tree:

```
touch → TouchRouter ─┬→ MoveStick.value            ─┐
                     ├→ LookStick.value            ─┤
                     ├→ LookPad.looked(pixels)     ─┤
                     └→ PauseButton.pressed        ─┤
                                                    ├→ Hud
keyboard → Input.get_vector()                      ─┘    │
                                                         │ get_move_intent()
                                                         │ get_look_intent()
                                                         │ look_requested(pixels)
                                                         ▼
                                                       Player
                                  set_move_intent() / set_look_intent() / add_look()
                                                         │
                                                         ▼
                                                 PlayerTuning (.tres)
```

`Player` never reaches for an input device and no stick ever hears of a camera.
Both look styles end at the same place by different routes: the right stick
sends *deflection* and the player integrates it into a turn rate, a drag sends
*travel* and the player applies it once. Swapping the scheme, or driving the
camera from a cutscene, touches one file: `src/main.gd`.

Continuous analogue state (stick deflection) is **read**; discrete events (a
drag delta arriving) are **signals**. Polling a value that exists every frame is
not the anti-pattern; polling for a change that already had an event is.

## Pause

Pausing is four things, and it is not a pause without all four:

1. `get_tree().paused = true` stops the simulation and physics.
2. `Hud.release_touches()` runs **first**, before the tree stops delivering
   input, so no stick is left deflected by a thumb whose release nothing will
   ever hear about. This is what makes a resume produce no camera jump.
3. The SFX, Music and Voice buses duck under the master (`AudioBuses`). Volume
   and duck are kept as separate numbers and combined on the way out — adding
   and subtracting a duck from a live volume looks equivalent and is not.
4. The menu announces itself to the HTML shell, which uses it as the safe point
   it has been holding an update banner for.

`PauseMenu` runs at `PROCESS_MODE_ALWAYS`; everything else pauses with the tree.

## Tuning resources

Anything that affects feel lives in an editable `Resource`, never in code:

| Resource | Governs |
|---|---|
| `src/player/player_tuning.tres` | walk speed, accel/brake, gravity, turn rates and the ceiling on them, drag sensitivity, look smoothing, invert-Y, pitch limit, eye height, FOV, head bob |
| `src/input/touch_tuning.tres` | deadzone, response curve, per-touch delta clamp, rest/active opacity, tint, accent, fade |
| `src/ui/hud_layout.tres` | where every control sits and how big it is: stick insets and radii, claim padding, the action arc, the pause button, the minimum touch target in points |

Adding a feel constant means adding an `@export` to the matching `*_tuning.gd`
with a comment saying what the number *means*, not what it is.

## Instrumentation

There is no console on a phone, no devtools, and no profiler. Three things stand
in for all of that, and each is tested in CI (`docs/TESTING.md`):

| | Where | What it answers |
|---|---|---|
| Build stamp | HTML shell, top-left | Which build is this? Tap it to copy the full report. |
| Debug overlay | `src/ui/debug_overlay.gd`, top-right | Is it fast? Is audio running? Is storage durable? Did the touch land? |
| Error toasts | `web/boot.js`, top-centre | What went wrong, instead of a silence. |

The overlay is summoned by a three-finger tap, which `src/input/touch_watch.gd`
recognises without consuming any touch — it observes through `_input()` and never
marks an event handled, so the stick and the look pad behave as though it were
not there. Three fingers because two happen constantly in normal play.

Half the overlay's numbers come from Godot's `Performance` monitors and half
from `window.__itaw_env()` in the shell, because DPR, safe-area insets, storage
health and worker state are things only the page can see. While the overlay is
open it publishes its sample to `window.__itaw_probe`, which is how the headless
suite asserts the frame budget and proves audio is being mixed — neither is
legible from a screenshot.

Error surfacing sits in the shell rather than in the game on purpose: it is
wired to `window.onerror`, `unhandledrejection`, **and** Godot's
`onPrintError` (which carries GDScript runtime errors), so it still works when
the engine is the thing that died. Repeats are folded into one toast with a
count, because one bad line in `_process` fires sixty times a second.

`src/world/lamp_hum.gd` synthesises a 120 Hz ballast hum at the bulkhead lamp.
It exists only to make the audio unlock audible on the device and is deleted in
P3, when real sound design replaces it.

## The web layer

`web/shell.html` replaces Godot's default page entirely. Godot substitutes
`$GODOT_PROJECT_NAME`, `$GODOT_URL`, `$GODOT_CONFIG`, `$GODOT_THREADS_ENABLED`
and `$GODOT_HEAD_INCLUDE`, then appends its own icon and manifest links.

The shell is markup, CSS, and a marker. Everything it *does* lives in
`web/boot.js`, which `postprocess_web.py` folds into `index.html` at the
`/* $ITAW_BOOT */` marker along with the contents of `build_stamp.json`. Two
files to read, one file at runtime — and that matters, because half of boot.js's
job is to be the recourse when the cache has gone wrong, which a separately
cached file could not be. The substitution is asserted at both ends: exactly one
marker must be present, and a sentinel from boot.js must be in the output.

The load sequence is deliberately split, because iOS only lets an `AudioContext`
start inside a user gesture:

```
page load ──→ engine.init(exe)          load the wasm
          ──→ engine.preloadFile(pck)   load the data, drive our progress rule
                     │
                     ▼  both resolved
              "TAP TO BEGIN" revealed
                     │
                     ▼  inside the tap handler
              engine.start(...)         Godot builds its AudioContext here,
                                        under the gesture, so audio is unlocked
                                        for the entire session
```

Godot's own PWA generation produces the manifest and service worker (cache-first
for engine assets, offline fallback page), which `tools/ci/service_worker.py`
then reworks into one that can be updated from a phone — see `docs/DEPLOY.md`
for the four changes and why each exists.
`progressive_web_app/ensure_cross_origin_isolation_headers` **must stay false**:
that option exists to enable `SharedArrayBuffer`, which we do not use and must
not require.

Godot's shell registers the service worker itself; ours does not call
`engine.installServiceWorker()` but registers directly, so it can choose the
moment: after the payload has landed, never during it. The install handler
re-fetches the shell files, and doing that while a 37 MB payload is still in
flight costs first-load time on the connection that can least afford it.

The shell also publishes `window.__itaw_safeArea()`, because `env(safe-area-inset-*)`
is readable only from CSS. `src/ui/safe_area_margin.gd` reads it through
`JavaScriptBridge` and turns it into HUD margins, which lets the 3D canvas stay
full-bleed while the UI stays clear of the notch.

## Build pipeline

```
tools/ci/build_web.sh
 ├─ stamp_build.py        write build_stamp.json (version, commit, branch, date)
 ├─ make_icons.py         regenerate art, then FAIL if it differs from what is
 │                        committed -- generated assets must never be hand-edited
 ├─ godot --import ×2     second pass resolves the class cache the first built
 ├─ godot --quit-after    boot the game headless; fail on any logged error
 ├─ godot --export-release
 ├─ postprocess_web.py    inline boot.js + the build stamp, content-hash the
 │                        payload, rewrite refs, assert the export is
 │                        single-threaded and non-isolated, copy _headers
 │   └─ service_worker.py  key the cache to the build, take over immediately,
 │                         network-first navigation, ?fresh=1 bypass -- every
 │                         edit asserted against Godot's generated output
 └─ check_budgets.py      fail on a budget breach
```

Content hashing is what makes `Cache-Control: immutable` honest: `index.wasm`
becomes `index.<sha>.wasm`, so a new build cannot be shadowed by a year-old
cached one, while `index.html` and the service worker stay `no-cache` and decide
which build is live.
